# JoyCode 0.3.16 — Early Preview

Build 28。本版适配 ChatGPT／Codex 26.1111 的 Chromium 内核并修复由此引起的锁死，新增 Y 回答选项卡，诊断事件写入 macOS 统一日志。

## 新增

- **Y 回答选项卡的第一项：**Claude Code 的“下一步”卡片点主选项（以 `aria-keyshortcuts="Meta+Enter"` 识别）；ChatGPT／Codex 的提问面板作答已选中或 Recommended 的选项，面板若有唯一的 Submit／Continue／Next 则先选再提交。单次 AXPress，不重试，不合成 ⌘↩；不提供手柄切换选项。
- Y 与 A 共用 1.5 秒提交冷却，同一张卡片只作答一次。录音／转写期间、输入框有草稿、Agent 运行中、审批或应用操作按钮、多选题和自由输入选项均拒绝。
- 只读选项卡诊断：菜单栏可检查当前选项卡结构并预演 Y 的定位，结果写入统一日志，不含文字。
- 诊断事件和手柄输入写入 macOS 统一日志（subsystem `local.weng.XboxAgentRemote`），可用 `bash logs.sh` 查看，`bash logs.sh errors` 只看失败。不记录草稿、转写或录音内容。

## 修复

- ChatGPT／Codex 26.1111 将内核由 Electron 改为 Chromium 157，录音按钮在基础模式下缺少 `AXPress`，且 `AXManualAccessibility` 不再受支持。现在改为请求 `AXEnhancedUserInterface`，仍等待 `AXPress` 出现后才开始录音。
- ChatGPT 侧边对话（side chat）不在支持范围：Codex 只选择主线输入框，按 X 时先把焦点移回主线。
- 原生转写完成、焦点已离开输入框时，恢复待命并保留草稿（不标记为可发送），不再锁死在不确定状态。锁定状态下原目标无法恢复时，RB／LB 仍把所属应用切回前台；连按两次 B 复位。
- 聚焦输入框后最多等待 1 秒确认焦点生效，修复 Chromium 异步聚焦导致的“输入焦点不在已确认的聊天输入框”误报。
- 开发构建可用 `JOYCODE_SIGN_IDENTITY` 指定固定签名证书，重新构建后不再丢失辅助功能授权。发布包仍为 ad-hoc 签名。

本地 232 项测试通过，安装包构建、签名和 SHA-256 校验通过。远端构建与发布结果见 [Actions](https://github.com/wengych/JoyCode/actions)。

## 验证边界与已知问题

- 实机通过：Codex 主线 X 开始／X 结束／B 取消；Claude X／X／A 发送；转写期间 A、B 被正确拒绝；侧边对话有焦点时首次按 X 即在主线输入框录音；Y 回答 Claude 5.11492.5 两按钮卡片和 Codex 计划提问（3 个选项）。
- 未复测：重启 ChatGPT 后经 Enhanced 请求首次启用 `AXPress` 的完整路径、锁定后 RB 激活回退、提问面板带提交按钮的路径。LB／RB 切换的完整轮次验收仍来自 0.3.12。
- **Codex 右摇杆滚动的最新实体测试失败，本版未修复。**
- **Codex A 提交尚未获得实体结果确认。**
- 滚动可能移动真实鼠标指针；进入转写阶段后需在 Agent 内手动取消。
- 应用仍使用 ad-hoc 签名，未经 Apple notarization；Bundle ID 保持 `local.weng.XboxAgentRemote`。

需要 macOS 14 或更新版本、Xbox 手柄及已适配的桌面客户端。解压应用后授予辅助功能权限，并在 JoyCode 中启用控制。

发布附件为应用 ZIP 与 `SHA256SUMS`，将两者放在同一目录后校验：

```bash
shasum -a 256 -c SHA256SUMS
```
