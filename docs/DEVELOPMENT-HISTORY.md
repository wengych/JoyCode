# 开发与验证记录

本文件保留 JoyCode 早期适配的主要演进、验证证据和未完成项。历史版本的测试数量与实体结果仅属于对应版本，不能替代当前客户端回归；本记录不包含个人路径、原始聊天内容或机器实例标识。

## 0.3.12 · build 24

本轮集中修复录音生命周期与重复提交风险。

- Codex 结束或取消听写后可能重建编辑器。现在只在原窗口、原局部范围仍一致且听写已空闲时，只读检查唯一合格的新编辑器；保留原录音所有权，不向新编辑器补发语音动作。取消仍要求草稿与开始前一致，完成仍要求文字稳定。
- 成功结束后清除旧输入框与滚动缓存；编辑器重建时丢弃旧发送就绪凭据，下一次 A 重新检查当前草稿。
- 原生 AXPress 尚未发出时遇到停用或断连，清除准备状态，不产生虚假的录音锁；请求已经发出且结果未知时，继续保留所有权和锁定。Typeless 不使用这一原生所有权判断。
- 异步任务使用独立忙碌令牌与操作代次；旧任务不能释放新任务的忙碌状态。转写观察器同时核对阶段、后端和目标，防止复位后的旧结果覆盖新操作。
- 停止或取消在动作发出前失败，且仍明确观察到原录音继续时，保留录音状态并提示重试，不自动点击。
- LB／RB 对称处理原窗口恢复。状态不明时，只有原录音窗口已在前台，且只读检查确认空闲，才继续跨 Agent 切换；不会先切到另一窗口探测状态。
- 在实际提交边界按目标记录提交尝试，并消费发送就绪状态。即使 AX 返回错误，同一目标、同一草稿也不能重复提交。切换应用或在其他目标发送不会清掉原记录；观察到同一编辑器内容改变或清空后才释放。
- 已进入转写阶段时，B 明确提示在 Agent 内手动取消，不将未适配动作当作已取消。

**自动验证：**198 项测试通过，比 0.3.11 新增 34 项，覆盖局部重建编辑器核验、旧任务令牌失效、取消草稿恢复和每目标提交去重。其中包含“目标 A 提交结果未知 → 目标 B 提交 → 返回 A”仍阻止重复的回归。发布构建无警告，签名校验通过。

**实体验证：**用户确认 Codex 连续两轮 X 开始 → B 取消 → LB／RB 切换正常；随后 X 开始 → X 结束 → 文字稳定进入草稿 → LB／RB 切换 → 再次 X 开始 → B 取消也通过。可再次开始录音，未再出现已取消却阻止切换的问题。

**最新未完成项：**Codex 右摇杆滚动收到明确失败反馈，本次预览发布不修复该问题。A 提交尚未确认：组合测试的反馈只说明滚动异常，不能据此推断发送成功。Claude 的较完整实体验收来自早期版本，不能视为 0.3.12 全键复测通过。异常状态只读恢复、断连和换窗竞态仍需更多实体回归。

## 0.3.11 · build 23

0.3.10 已成功定位输入框，但 X 随后失败在原生语音初始快照的命中检查：轮询尚未开始、动作列表尚未读取，也未发出录音请求。

0.3.11 将状态读取与最终操作前的精确命中等待分开。几何、身份和动作读取失败明确报错，不把命中失败当作刷新 `AXManualAccessibility` 的理由。开始、停止和取消最多等待 1.5 秒，每 50 毫秒检查同一按钮中心；其他位置的命中检查在此之前完成，等待中不穿插输入框命中。必须命中原按钮或其内部子元素，祖先、相邻控件、其他进程和窗口均不能代替。目标、操作代次或草稿基线变化即停止，通过后仅发出一次 AXPress，不重试点击。

Chromium 的命中缓存机制为此前现象提供了有证据支持的解释，但没有证实本机每一次失败都由缓存导致。

164 项测试、发布构建与签名校验通过，新增 10 项异步等待测试。用户确认 X 能开始、B 能关闭录音界面；随后日志揭示取消后编辑器 AX 对象重建，导致内部结果核验失败，进入状态不明并阻止 LB／RB。确认录音实际取消后进行了手动复位；该版本没有通过完整取消恢复验收。

## 0.3.10 · build 22

0.3.9 的首次实体测试中，连续三次 X 都在“无法唯一识别主聊天输入框”处停止，未请求录音。代码审查确定旧匹配器会把带通用 reply／message 标记的只读内容纳入候选，复用 Claude 标记也会引入 Codex 歧义；当时日志未记录候选明细，不能断言这就是三次失败的实际原因。

0.3.10 增加独立的 Codex 编辑器规则：可访问名称完整匹配已证实标签，且 `AXValue` 必须明确可写。未知名称、只读、可写状态不明及仅 placeholder 匹配的控件均不合格。优先选择唯一已聚焦的合格编辑器，再选择唯一主区域且非 complementary 侧栏候选，最后检查唯一非侧栏候选；仍有歧义就拒绝。

发送、语音验证和滚动共享这一规则；局部范围额外计入所有可写、可见输入框，未知名称的第二个输入框也会阻断动作。诊断仅记录固定类别、计数和布尔证据，不记录实际名称、草稿或转写。

154 项测试通过，包含 17 项独立输入框规则测试；发布构建和签名校验通过。现场日志先记录 `known=2`、`editable=3`、`eligible=2`，正确区分主输入框和侧输入框，后续记录唯一主输入框且 `focus=true`，确认输入定位成功。新的失败发生在原生快照命中检查阶段，不再是输入框选择阶段。

## 0.3.9 · build 21

新增 Codex 原生听写、提交与回复区适配。使用已证实的英语、简体及繁体中文标签匹配 `Dictate`、`Stop dictation`、`Cancel dictation`／`Cancel transcription`。Codex 取消使用原生按钮，不回退 Esc，因为 Esc 可能将转写插入草稿；不点击 `Transcribe and send`，完成后先保留草稿供检查。

A 遵循当前输入框默认 `Send`、`Queue` 或 `Steer` 行为，拒绝 `Stop`、`Resume`、语音聊天及听写控件。滚动只接受明确标为 `Conversation`／对话／對話的区域。身份、范围、可见性和动作校验均保留。

137 项测试、发布构建与签名校验通过。首次实体 X 连续三次因输入框歧义停止，不能将静态适配和测试通过视为 Codex 客户端联调完成。

## 0.3.8 · build 20

收到 Codex 空闲时按 A 拉起 Claude 的反馈。旧日志仅显示 Codex 激活后出现 Claude 原生听写开始，缺少原始按键记录，无法确认 A 就是实际触发源。

本版增加动作触发时的前台应用、进程及窗口身份诊断，不记录窗口标题或输入文本。A、X、B、方向键和摇杆按实际前台路由，并在异步等待和动作边界继续核对同一窗口；不使用上次选中的 Agent 回退。删除 X 自动激活 Claude 的路径，只有肩键及明确的激活／打开入口可以主动切换窗口；同时移除会隐式激活目标的语音调试按钮。

113 项测试、发布构建与签名校验通过，新增 11 项覆盖前台路由、语音锁、应用／进程／窗口变化及拒绝后的零副作用。用户仅确认不再跳到另一应用，没有完成全键实体验收。

## 0.3.7 · build 19

方向键按实际前台切换对应应用的会话，不再自动激活 Claude。Claude Code 使用 `Previous Session`／`Next Session`；Codex 使用 `Previous Sidebar Item`／`Next Sidebar Item`，每次请求一次菜单 AXPress，不使用切文件标签页的 `Previous Tab`。

Codex 导航遵循可见侧栏顺序，在混合侧栏中可能选中 Page 或附件，并非只筛选聊天。102 项测试、发布构建与签名校验通过；用户确认两边前台的方向键导航均正常，且不会跨应用跳转。

## 0.3.6 · build 18

新增 RB 激活 Codex，通过 NSWorkspace 激活并核验实际前台 Bundle ID 和进程；LB 继续激活、聚焦 Claude。此时 Codex 仅提供显式激活，后续功能另行适配。

98 项测试、发布构建与签名校验通过。设置按钮和实体手柄均验证 Claude／Codex 来回切换正常；用户确认 Claude 物理键盘不重复、A 只发送一条、右摇杆上下滚动且松开停止。滚动会移动真实鼠标指针，这一限制保留至当前版本。

## 0.3.4—0.3.5 · Claude 原生听写

早期 Claude 原生听写遇到麦克风未声明 AXPress、开始后未观察到录音，以及状态不明后无法返回的情况。只读等待不能可靠恢复动作列表，随后增加受限初始化：同一个空闲、已启用的麦克风缺少 AXPress 时，最多设置一次 `AXManualAccessibility=true`；已有近期成功请求则复用等待，避免重复写入。不使用 Enhanced 模式，不写入 false，不强行调用未声明的动作。

0.3.4 现场刷新成功：20 次轮询约 2.250 秒后，动作从 `AXShowMenu`、`AXScrollToVisible` 增加为包含 `AXPress`；随后录音及取消成功，取消后草稿未变。另一次实际操作虽观察到动作就绪，但开始后的 30 次轮询未确认录音，进入状态不明，之后客户端实际已空闲。

0.3.5 增加原目标只读空闲恢复和返回窗口路径。只有原窗口、会话、输入框和麦克风仍一致，控件空闲、输入框可编辑，且连续 5 次、跨度约一秒读到稳定草稿，才清除锁定和旧发送就绪状态；不自动开始或发送。

98 项核心测试包含 7 项空闲恢复测试。实体连续两轮 X 开始 → X 结束 → 再次 X 开始 → B 取消成功，且可再次开始；日志记录一次刷新约 2.165 秒、AX 请求成功，随后文字稳定，第二轮取消后原草稿不变。真实客户端的状态不明恢复分支当时尚未复现验收。

## 早期 Typeless 与滚动适配

最初通过外部映射软件把 X 映射到 Typeless 快捷键，A 映射到 Enter；随后改为原生应用直接读取手柄，增加目标窗口定位、取消、会话导航和滚动。

0.1.6 的实体基线包含 LB 激活、Typeless 下 X 起止、A 单次发送、B 取消、方向键导航及物理键盘不重复。曾出现物理键盘重复输入，退出遥控器后仍存在，完整重启 Claude 后消失；具体原因没有得到证明，不能仅凭后续事件发送调整就认定根因已查明。

右摇杆早期无效果，改为核验回复区并在有效位置投递滚动后，用户确认能滚动和回中停止，但真实鼠标会移动。后续改为按实际时间累计位移、保留小数余量，并在回中、暂停或换窗时清空余量；这些变化不等于 Codex 当前滚动已经通过验证。

Typeless 保留为可选后端，支持全局与按应用快捷键、左右修饰键和 Fn。已验证的结束路径为快捷键；录音条完成按钮路径、各类快捷键与失焦恢复仍需更多专项验证。

## 当前发布边界

- Codex 滚动明确失败，尚未修复；A 提交尚未得到实体确认。
- 当前已确认的是 Codex 原生听写起止、取消、重入及 LB／RB 切换，不能扩大为全键验收。
- B 在转写阶段需要用户到 Agent 内手动取消；手动复位本身不会停止 Agent 的录音或转写。
- 仍需补充录音结果未知、断连、切窗、停用及手动恢复的实体场景；自动测试不替代客户端测试。
- 真实鼠标指针可能随滚动移动；客户端更新、语言或布局变化也可能导致拒绝操作。
- 分发包使用本地 ad-hoc 签名，未进行 Apple notarization。兼容配置域和 Bundle ID 保持 `local.weng.XboxAgentRemote`，内部可执行文件名保持 `XboxAgentRemote`。
